## 01 / Problem

Job seekers juggle disconnected tools: job boards, resume editors, spreadsheets for tracking, and interview notes. CareerOS brings discovery, resume feedback, preparation, and tracking into one personal workspace — explicitly not an "apply everywhere" bot: tracking an application never submits it; users apply through the original listing.

## 02 / Architecture

<CareerosStepper />

Profile and preferences compile into a search strategy (synonym expansion, keyword optimization), sources are queried concurrently with retry and rate limiting, results are normalized into one schema, deduplicated (exact hash plus fuzzy similarity), filtered against job memory (seen, saved, ignored, applied), scored, ranked, and delivered to the dashboard and Telegram digest:

<Figure caption="CareerOS discovery pipeline (full platform)" note="Free deployment runs a subset; see limitations.">
  <CareerosPipeline />
</Figure>

- **Backend** — FastAPI + SQLAlchemy 2.x + Pydantic v2; 20 route modules (auth, profile, search, applications, Telegram, dashboard, billing, ATS, outreach); 14 model files covering 30+ tables; JWT auth with PBKDF2 hashing.
- **Search pipeline** — strategy builder, multi-source aggregator (Remotive, RemoteOK, Wellfound, YC, StartupJobs, plus Bangladesh sources), 10-factor weighted scorer (role fit 30%, skill fit 25%, experience 15%, remainder across location, stack, company, salary), ranker blending match score, freshness, novelty, and preference.
- **Scheduler and alerts** — APScheduler for periodic runs with duplicate protection; Telegram digests with save/ignore/prepare actions.
- **Frontend** — Next.js 14 dashboard (13 pages): profile, search settings, saved jobs, job detail, application workspace.
- **Deployment** — Docker Compose (5 services: web, frontend, Postgres 16, Redis 7, Telegram worker); live free tier runs the same codebase on Azure F1 with SQLite and local file storage.

<section id="decisions" className="tab-panel">

## 03 / Engineering decisions

- **Local rules instead of paid AI in the free tier.** Resume ATS feedback and skill-gap analysis run on local heuristics, keeping the free deployment cost-free and deterministic. The trade-off is shallower feedback than LLM generation; paid generation exists in the codebase but stays disabled live.
- **Explicit non-goals.** No automatic application submission, no continuous background workers in free mode, no email/password registration (Google sign-in only). Each exclusion is documented on the live site.
- **History-aware search.** Job memory filters already-seen roles before ranking, so repeat searches surface only new opportunities; fuzzy dedup (0.65 threshold) merges cross-source duplicates.
- **Security hardening as releases, not afterthoughts.** Past releases closed IDOR and data-leakage gaps, separated staff login from customer auth, removed secrets into environment configuration (gitleaks + baseline tracked), and deploy through Azure OIDC without stored credentials.

<section id="limitations" className="tab-panel">

## 05 / Limitations and next steps

- The live free tier runs on Azure F1 quotas: SQLite instead of PostgreSQL, local file storage instead of Blob storage, cached Remotive feed with 24-hour listing delay and refreshes at most every six hours.
- Disabled live: paid AI generation, billing/subscriptions, continuous scheduling, email delivery, password recovery.
- Authenticated staff browser testing was still pending at the last verified release; checks do not establish exhaustive coverage.
- No independent performance or security audit beyond the project's own gates.

Next steps per the codebase's own split: enabling the already-implemented billing, scheduler, and paid-AI modules beyond the free tier, and completing staff-side verification.
